# SD Hub – GitHub Collaboration Practice

Welcome to the **SD Hub Git Collaboration Repository!**

This repository is created as part of our Web Development training at **Skills Development Hub** to gain practical experience with Git and GitHub and understand how developers collaborate on shared projects.

Our objective is to learn the actual development workflow by contributing to a common project through individual branches and Pull Requests.

---

## 🎯 Objectives

- Understand Git and GitHub fundamentals.
- Learn how to clone and manage repositories.
- Create and work with individual branches.
- Make changes without affecting the main branch.
- Stage, commit and push code changes.
- Create and submit Pull Requests.
- Understand code reviews, merging and collaboration.

## 🚀 Getting Started

### 1. Clone the Repository

```bash
git clone https://github.com/ammaarquadri/SD-Hub-Git-Collaboration.git
```

### 2. Navigate to the Project

```bash
cd SD-Hub-Git-Collaboration
```

### 3. Create Your Own Branch

Create a separate branch using your name:

```bash
git checkout -b feature/your-name
```

Example:

```bash
git checkout -b feature/ahmed
```

### 4. Make Your Changes

Open the project in VS Code and make at least one small modification to the existing webpage.

You can:
- Modify a heading or paragraph.
- Improve CSS styling.
- Adjust spacing and alignment.
- Add colours or typography.
- Improve the webpage layout.

**Important:** Work only on your own branch.

### 5. Stage and Commit Your Changes

```bash
git add .
git commit -m "Updated webpage styling"
```

### 6. Push Your Branch to GitHub

```bash
git push -u origin feature/your-name
```

### 7. Create a Pull Request

1. Open the repository on GitHub.
2. Navigate to the Pull Requests section.
3. Click **New Pull Request** or **Compare & Pull Request**.
4. Select your branch as the source and `main` as the destination.
5. Add a short description of your changes.
6. Click **Create Pull Request**.

Your contribution is now submitted for review!

---

## 📌 Collaboration Guidelines

1. Every contributor must work on an individual branch.
2. Do not push changes directly to the `main` branch.
3. Make meaningful and identifiable commits.
4. Avoid modifying or deleting another contributor's work.
5. Always review your changes before creating a Pull Request.
6. Communicate with the team if merge conflicts occur.
7. Wait for review before merging your Pull Request.
